# modern-di-flask 3.1.0 — adopt the modern-di 3.1 lifecycle

modern-di 3.1 relaxed two things this integration leaned on: a container is now
**open from construction**, and graph validation happens only when you call
`container.validate()` — `open()` no longer runs it. This release adopts that
contract in the adapter, the docs and the tests.

**No public API change.** `setup_di`, `fetch_di_container`, `FromDI`, `inject`
and `flask_request_provider` keep their signatures and behavior.

**Requires `modern-di>=3.1`** (was `>=3,<4`). See Downstream.

## Fix

- **The documented setup no longer passes `validate=True`.** In modern-di 3.1
  that argument is a deprecated no-op that emits `ValidateArgumentWarning`, so
  the README example emitted a `DeprecationWarning` on every construction — and,
  more quietly, silently stopped validating anything, because it *was* the
  explicit opt-in. The docs now build the container plain and call
  `container.validate()` **after** `setup_di`. The ordering rule is unchanged
  and still load-bearing: `setup_di` is what registers `flask_request_provider`,
  so validating first fails any provider with a non-optional `flask.Request`
  dependency.

- **The suite was red against modern-di 3.1.** A test asserted that
  `container.open()` raises `ValidationFailedError` when called before
  `setup_di`. In 3.1 `open()` validates nothing, so it does not raise. The rule
  that test guards still exists — it just binds `validate()` now — so both it
  and its sibling were rewritten to that call rather than deleted.

- **The README and `architecture/dependency-injection.md` said `.open()` was
  "required under modern-di 3.x's mandatory-open lifecycle" and that
  `validate=True` "runs at `open()` time".** Neither is true in 3.1. Both are
  corrected. The genuinely caller-owned half is unchanged and still documented:
  Flask has no application-shutdown hook, so `fetch_di_container(app).close_sync()`
  at your shutdown point is still yours to call.

## Performance

- **The per-request `child.open()` is gone.** `_enter_request` built the request
  child and then opened it; under modern-di 3.1 that child arrives open, so the
  call only re-acquired the container's lock on every request — roughly 81 ns of
  pure indirection per request. This is what the floor bump buys: under 3.0 a
  child was built *closed* and the call was mandatory.

  Removing it is safe here because nothing reopens the child mid-request —
  `close_sync()` runs once, from `teardown_appcontext`, and the `@inject` path
  only reads the child off `flask.g`. Adapters that close a child per `@inject`
  frame keep their `open()`, because there it revives a container a previous
  frame closed.

## Downstream

**Upgrade `modern-di` to 3.1 or newer first.** This release requires
`modern-di>=3.1,<4`; on 3.0.x the removed `child.open()` was mandatory and every
request would raise `ContainerClosedError`. Nothing else is required of you.

If you copied the old README snippet, drop `validate=True` — it does nothing on
modern-di 3.1 and warns:

```python
container = Container(groups=[Dependencies])
setup_di(app, container)
container.validate()  # optional fail-fast; flask_request_provider is registered by now
```

Keeping it works, but emits a `DeprecationWarning`, and a suite configured with
`error::DeprecationWarning` will fail on it. The argument is removed in
modern-di 4.0.
