# Design: Canonical minimal-DI example (flask rollout)

## Summary

Ship a canonical, runnable example in `modern-di-flask`: a minimal
`examples/` app wiring one `Settings` (APP scope) and one `GreetingService`
(REQUEST scope) into a route via the real `@inject` + `FromDI` idiom, an
in-memory smoke test that proves it runs, and the README `Usage example:`
line the audit found missing. This flips the two coupled gaps the
blessed-ready audit scored on this repo — **D2 (canonical example) 1 -> 2**
and **D6 (README consistency) 1 -> 2**. This is the first rollout repo after
the locked `modern-di-faststream` pilot
([2026-07-24.01](https://github.com/modern-python/modern-di-faststream/blob/main/planning/changes/2026-07-24.01-canonical-example-onramp.md)):
same Settings+Service shape, adapted to flask's `@inject`/`FromDI`-marker
idiom (no `Depends` seam) and its `setup_di`-after-routes ordering
constraint.

## Motivation

The [blessed-ready on-ramp audit](https://github.com/modern-python/modern-di/blob/main/planning/audits/2026-07-22-blessed-ready-onramp-report.md)
found 10 of 12 integrations at **D2=1 / D6=1**: a complete inline README
example but no *dedicated, linked* canonical example, so neither the `Usage
example:` line (D6) nor a D2=2 score is reachable. flask is one of the nine
rollout repos identified in the pilot's non-goals.

## Design

**The example** — `examples/app.py` (+ `examples/__init__.py`): the smallest
runnable flask app that demonstrates the recommended wiring, matching the
README snippet's shape but as a complete program:

- `Settings` — `providers.Factory(scope=Scope.APP, creator=Settings)`.
- `GreetingService` — `providers.Factory(scope=Scope.REQUEST, ...)`, depends
  on `Settings` by type (auto-injected).
- one `@app.route(...)` view decorated with `@inject`, taking the service via
  `typing.Annotated[GreetingService, FromDI(Dependencies.service)]` — flask
  has no `Depends` seam, so injection is the marker-annotation form the
  existing tests already use, not a default-value marker.
- `setup_di(app, container)` is called **after** the route is registered (the
  README's documented ordering rule), and `container.open()` runs
  **after** `setup_di` — `setup_di` registers `flask_request_provider`,
  which `validate=True` checks for at `open()` time. A `# run: flask --app
  examples.app run` header comment states the real-run command.

**Smoke test** — `tests/test_example.py`: imports the example's `app`, and
using the repo's existing in-memory idiom (`app.test_client()`, already used
in `tests/test_inject.py`/`test_auto_inject.py`) issues one GET and asserts
the real greeting text the injected `GreetingService` produced. This proves
the example runs with no infra, and keeps it from rotting.

**Coverage** — none excluded. The smoke test executes `examples/app.py` end
to end (import wires the app, container, route, and opens the container; the
request runs the view), so it covers the example to **100%** under the
repo's existing `--cov-fail-under=100` gate. No `omit` is needed — the
example is real, measured, tested code.

**README** — insert `Usage example: [examples/](./examples)` directly under
the `Full guide` line, matching the faststream pilot's placement. The
existing inline `## Usage` snippet stays — the example is its fuller,
runnable form.

No `modern_di_flask/` source changes, so no `architecture/` promotion — this
adds documentation-grade example + test, not a capability change.

## Non-goals

- The remaining rollout repos and the core `writing-integrations.md`
  codification — tracked separately, referencing this and the faststream
  pilot's locked pattern.
- A realistic/DB starter — minimal DI demo only (the audit's chosen
  ambition).
- New runtime dependencies — the example uses only `flask` + `modern-di`,
  already present.
- Editing the inline README snippet or any integration behavior.

## Testing

- `just test-ci` green: the smoke test covers `examples/app.py` to 100% (no
  exclusion) and hits a real route asserting the injected service's real
  output (not a mock).
- `just lint-ci` green (ruff/ty/eof/format over the new files).
- `just check-planning` green (this bundle validates).
- Manual sanity: `flask --app examples.app run` starts and serves
  `/greet/<name>` (documented, not a CI gate).

## Risk

- **Example rot** (low x low) — mitigated structurally: the example is
  measured (no coverage exclusion) and the smoke test executes it every CI
  run, so a broken or uncovered example fails the build.
- **Example drifts from the README snippet** (low x low) — they share one
  shape; keep the example the runnable superset of the snippet.
- **`setup_di`/`container.open()` ordering regresses** (low x medium) — this
  repo's README ordering rule (routes before `setup_di`, `open()` after
  `setup_di`) is easy to get backwards; the example is the ordering's
  executable proof, and the smoke test fails loudly if it regresses.
